# LifeOS: запуск, проверка и безопасное обновление MVP

## 1. Перед запуском

Нужны Node.js, pnpm, Python 3 и приложение Expo Go на телефоне. Не публикуйте файлы `.env` или ключи API в GitHub, чатах и скриншотах.

В корне проекта должны быть:

- `.env` — только серверные параметры: `OPENROUTER_API_KEY` (или ключ другого выбранного провайдера), `SUPABASE_URL`, `SUPABASE_SECRET_KEY`;
- `apps/mobile/.env` — публичный адрес API, Supabase URL и publishable key;
- локальный сервис распознавания голоса, если включена голосовая запись.

Ориентиры для названий переменных есть в `.env.example` и `apps/mobile/.env.example`. В примерных файлах должны быть только значения-заглушки.

## 2. Однократная настройка Supabase

В SQL Editor выполните по порядку:

1. `docs/supabase/001_initial_schema.sql`;
2. `docs/supabase/002_habits.sql`;
3. `docs/supabase/003_goals.sql`;
4. `docs/supabase/004_processing_jobs.sql`.

После запуска убедитесь, что таблицы `life_records`, `record_artifacts`, `profiles`, `processing_jobs` видны в Table Editor. Не отключайте RLS: он ограничивает доступ к данным владельцем аккаунта.

## 3. Локальный запуск

Откройте два окна PowerShell в папке проекта.

В первом окне запустите API:

```powershell
& "C:\Program Files\nodejs\pnpm.cmd" --dir apps/api start
```

Во втором окне запустите Expo:

```powershell
& "C:\Program Files\nodejs\pnpm.cmd" --dir apps/mobile exec expo start --lan --clear
```

Если используется голосовая запись, в третьем окне запустите локальную расшифровку:

```powershell
py -3 tools/local_transcriber.py
```

Компьютер и телефон должны быть в одной Wi-Fi сети. После изменения `apps/mobile/.env` обязательно перезапускайте Expo с `--clear`.

## 4. Проверка перед демонстрацией

1. Откройте приложение через Expo Go.
2. Войдите в аккаунт.
3. Напишите короткую мысль, выберите настроение и получите AI-анализ.
4. Проверьте, что запись появляется в истории после перезапуска приложения.
5. Создайте привычку и цель, отметьте привычку выполненной.
6. Удалите тестовую запись и убедитесь, что она исчезла из истории.
7. При желании проверьте голосовую запись: аудио расшифровывается локально, а в историю сохраняется только текст и анализ.

## 5. Проверка кода

Перед отправкой изменений в GitHub выполните в корне проекта:

```powershell
& "C:\Program Files\nodejs\pnpm.cmd" test
& "C:\Program Files\nodejs\pnpm.cmd" typecheck
& "C:\Program Files\nodejs\pnpm.cmd" build
```

Все команды должны завершиться без ошибок. Затем проверьте `git status` и убедитесь, что `.env` не попал в список файлов для commit.

## 6. Безопасное обновление

1. Сначала сохраните изменения в Git commit.
2. Выполните проверки из раздела 5.
3. При наличии новой SQL-миграции сначала запустите её в Supabase.
4. Отправьте commit в GitHub.
5. Перезапустите API, Expo и — при использовании — локальный сервис расшифровки.
6. Повторите короткую проверку из раздела 4.

## 7. Если что-то не работает

- `Network request failed`: проверьте IP-адрес компьютера в `EXPO_PUBLIC_LIFEOS_API_URL`, Wi-Fi и работу API.
- `status 429`: лимит AI-провайдера исчерпан; используйте действующий ключ или подождите обновления лимита.
- Ошибка авторизации Supabase: перезапустите Expo с `--clear` и войдите заново.
- Ошибка Expo: остановите сервер `Ctrl+C`, затем снова запустите команду из раздела 3.

Не отправляйте в чат полный лог с ключами, файл `.env` или личные записи пользователя. Для диагностики достаточно текста ошибки и названия команды, которая её показала.
